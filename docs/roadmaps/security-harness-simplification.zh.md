<a id="outcome"></a>
## 目标体验与首版范围

目标用户路径为：配置工作区 → 自然语言任务 → 简明进度 → 发现与交付物 → 在同一对话中继续。用户可以指定文件、环境、设备、限制和输出要求。系统仅在缺少影响有效推进的信息，或当前请求尚未提供所需权限时询问用户。

首条完整样例采用 Web 源码和本地测试应用。后续样例覆盖含嵌入式 Web 组件的固件，以及 IoT 协议文档或离线抓包。真实设备检查需要单独验证环境；离线成功不能证明硬件支持。普通开发、文件分析和研究仍属于同一 harness 的使用体验。

首轮实现保留在现有实验性安全组合中，复用 DSH 的 agent loop、Session、子 agent、jobs、工具、技能、沙箱与网络搜索。本计划不新增通用执行服务、调度服务、搜索服务或必需的向量存储服务。

<a id="responsibilities"></a>
## 复用基础与职责设计

[安全工作台](../subsystems/security-workbench.zh.md) 维护现有领域记录。以其 journal、不可变制品、provider 生命周期、资源互斥、复核和报告为基础。工作台阶段用于给单项检查分类，不代表强制四阶段流程。实施时需要区分这条路径与 legacy 提示词及测试。

| 职责 | 计划处理方式 | 实现归属 |
|---|---|---|
| 工作区默认配置 | 关联可复用的环境和材料引用；凭据仅保存引用 | 安全领域及现有工作区 API |
| 任务上下文 | 记录目标、请求范围、输入、资源、限制、交付要求与修订版本，并绑定发起 Session | 现有 controller 与领域 journal |
| 调查 | 仅在必要时扩展检查记录，表达事实、假设、替代解释、验证与停止条件 | 现有检查与发现记录 |
| 工具指导 | 扩展指导，说明适用条件、前置条件、允许影响、结果解释和失败处理 | 现有 provider 定义与技能 |
| 委派 | 分离分析专长与执行权限；创建子 agent 前解析允许的资产和能力 | 现有委派与 Session 绑定 |
| 证据与交付 | 保留原始观察、制品身份、复核指纹和修订报告；视图派生自已提交记录 | 现有制品、journal、复核与报告生成 |

安全记录以领域 journal 为准。Session 日志保留模型实际看到的上下文和工具结果，并稳定引用对应领域修订版本。UI 从已提交数据派生视图。本计划不为任一状态增加第二份可独立修改的副本。

<a id="delegation-design"></a>
## 根据缺失证据调度子 agent

这是阶段 4 的拟议设计，尚未实现为调度行为。用户提供的对比表用于指导优先获取新观察，避免重复讨论；它不代表 DSH 已测得相应收益。只有子 agent 能解决明确的未知项、覆盖不同任务范围，或承担有理由的独立复核时才委派。主 agent 始终负责目标、范围、证据整合与最终答复。

### 准入与反馈选择

创建子 agent 前，明确还不知道什么、哪种观察能区分不同解释、哪个可用能力能取得该观察，以及结果会如何改变下一步决策。先检索已有项目证据，复用仍适用的观察；时效性、目标变化或明确的可重复性实验可以构成重新测量的理由。新时间戳、另一份摘要或另一个模型的赞同都不属于新的目标证据。

| 工作 | 有用输入或反馈 | 调度决策 |
|---|---|---|
| 重读作者答案或围绕同一摘要辩论 | 没有额外观察 | 留在当前上下文，不为征求赞同单独创建子 agent |
| 调查独立组件或信任边界 | 不同源码路径、二进制函数、调用者或协议阶段 | 针对不可变输入并行调查不同问题 |
| 检查疑似实现缺陷 | 目标代码、执行日志、断言与阴性对照 | 先执行能区分假设的检查，再判断结果 |
| 检查页面渲染或交互 | 实际截图、DOM 状态和交互记录 | 验证要求的行为；仅凭截图不能确认服务端授权 |
| 核实外部事实 | 一手文档、适用版本和已配置工具的观察 | 使用 DSH web search 或适用 provider；外部资料不能证明目标存在漏洞 |
| 复核重要结论 | 精确结论以及原始支持证据和相反证据 | 使用独立复核上下文；请求具体缺失观察，避免再次辩论 |

Web、固件和 IoT 作为专长与方法提示，不对应强制创建的团队。含内嵌 Web 应用的固件任务，可拆分原生请求处理函数与 Web 授权路径，在共同输入处汇合结果。较小的源码问题，如果委派收益不足以抵消上下文和协调成本，就由主 agent 完成。模型多样性是可选项，本身不能满足证据要求。

### 调查、验证与复核

这三者是工作目的，不是新增的三种权限角色。优先复用兼容的现有任务与角色绑定。当前 [reviewer](../../packages/experimental/security-analysis/src/workbench/roles.ts) 可以读取证据和记录判定，但不能采集观察或执行验证；保留这一限制。分析者可以提出并执行获准的静态采集，运行时检查由协调者通过已有的计划审批、执行与清理机制安排。浏览器或设备检查必须具有实际可用的 provider 和相应授权，不能因为子 agent 将其称为验证就获得执行权限。

测试、扫描或渲染已有明确执行参数时，直接走现有工具和 job 路径，不为该调用分配 LLM 子 agent。只有方法选择、独立范围调查或证据的独立判断需要较多推理时，才创建子 agent。协调者可以直接消费工具反馈，自行完成较小任务。

调查提出假设及其成立条件；验证取得检验假设所需的观察；复核判断精确结论是否由原始观察支持，检查替代解释并指出缺失证明。复核者取得结论及定位相关工件所需的引用，不继承作者的讨论过程或信心评分。重新检查原始证据可能发现推理错误，但这是分析纠正，不是新增测量。保留有价值的静态复核，同时明确区分这两种贡献。

闭环为：问题 → 已有证据 → 缺失观察 → 获准采集 → 证据整合 → 按需复核 → 结论。复核指出缺口时，为该缺口建立检查；没有可用能力时，保留明确的未知项。不能通过再次发起相同复核，把无法判断变成一致赞同。既有结论策略要求独立复核的场景仍必须复核；低成本信息任务不额外强制经过复核者。

### 子任务输入与持久结果

仅对现有问题、完成条件、资产绑定和预算尚未表达的信息扩展委派请求。解析后的任务需要工作目的、已知证据引用、预期反馈、完成条件、依赖关系、分配的资产与资源，以及结论或任务修订。输入引用缺失或不可访问时，在分配子 agent 前拒绝。专长提示不能增加能力、资产范围或审批权限。

保留现有摘要、证据引用、不确定性与下一步，仅增加区分新增观察、基于已有证据的纠正、矛盾、受阻能力和请求检查所需的结果信息。Host 校验证据引用和目标身份，主 agent 判断结果实际解决了什么；子 agent 自报的新颖性或信心不具有权威性。原始字节、采集参数、环境身份和完成状态归属现有证据记录，实际送入模型的上下文记入 Session 日志。

用问题得到解决、假设得到支持或被反驳、新范围得到覆盖，或识别出能阻止重复无效操作的具体能力阻塞来判断进展。证据数量和工具调用次数不是质量分数。重复观察可以增强预先定义的可重复性实验；其他等价结果应合并处理，同时保留各自原始记录。新的解释可以支持纠正结论，但不能伪称采集了新字节。

### 依赖、预算与停止

通过已有检查、jobs 和子 agent 接纳依赖已满足的工作。有容量时并行启动相互独立的检查；对共享设备、调试器和可变环境，通过资源所有权串行执行。优先处理影响最终安全判断且能用现有资源回答的问题。取消后，先完成 provider 清理和资源释放，再重新分配；某个分支受阻不必阻塞其他独立分支。

增加覆盖主 agent 与全部子 agent 的任务级累计计量，包括 token、执行时间和重复无效工作。准入前预留额度，完成后结算实际使用量，并为证据整合与最终答复预留容量。复用已有并发数和时限配置，新增的部署差异参数必须可配置。资源与预算准入由 Host 执行，不能只写进提示词。计入在途工作，并明确不可避免的取消延迟或 token 超限。

问题达到所需证据标准、没有可行观察能消除剩余缺口，或任务预算耗尽时停止。连续无进展达到配置上限后，不再通过创建更多子 agent 延长循环。结论、输入身份或范围变化时，使依赖它们的待定判断失效；保留历史观察，取消不兼容工作，并在使用已完成结果前重新检查适用性。不得用过期复核认可修改后的发现。

### 用户体验与验收

用户必经路径不出现 agent 选择和内部任务图。进度表达实际结果，例如源码定位完成、正在检查触发条件或设备验证不可用。结论同时展示证据、成立条件、局限和修复建议；子 agent 活动与工具细节放入可选详情。仅在缺失信息或授权阻止下一项有用动作时询问用户。

以 Web 对象归属检查为例，先检查处理函数及调用路径。需要运行时验证且存在已授权的本地目标时，对同一对象比较所属用户与非所属用户请求，保留请求和响应记录；环境初始化失败或无关 HTTP 错误不能作为访问被拒绝的证据。随后由复核者对照两组响应和源码位置判断结论。目标不可用时，保留静态结论并明确运行时可达性未验证。固件或 IoT 使用对应函数、解析器、捕获数据或设备观察替代这些输入，决策过程保持一致。

验收需在同模型、同输入、同预算下比较：仅主 agent、重复摘要复核、基于观察的委派。同时包含能获益的任务和应该拒绝委派的任务。测量有证据支持的结论、误报、解决的问题、重复采集、复核纠错、延迟、主子 agent 总用量及用户介入次数。阈值在基线测量后确定；本计划不承诺尚未测得的数值收益。

<a id="steps"></a>
## 实施步骤

每阶段结束时同步交付行为证据和文档。仅在观察到要求的结果后勾选步骤。不可用的外部环境继续作为验收缺口记录。

### 1. 建立基线与可执行样例

依赖：无。主要位置：[安全测试](../../packages/experimental/security-analysis/tests)、[安全 preset](../../packages/experimental/security-profile/presets/security/agent.cordis.yml)、[角色定义](../../packages/experimental/security-analysis/src/workbench/roles.ts) 与[领域类型](../../packages/experimental/security-analysis/src/workbench/model.ts)。

- [x] S1.1 检查实际启用的 profile、工具组合、执行限制、操作者专属动作、委派和持久化；将行为分类为保留、改造或延后。
- [ ] S1.2 准备可重复的 Web、固件与嵌入式 Web、IoT 离线样例，记录已知问题、反例、输入身份和环境要求。
- [ ] S1.3 使用相同模型、输入和预算运行通用 DSH 与当前安全组合，记录发现质量、工具失败、重复劳动、成本和用户介入次数。
- [ ] S1.4 将普通文件与开发任务、已知分析错误纳入对照集，包括缺乏依据的 ELF 分析结论。

交付物：范围明确的样例集与基线测量。验收：区分实现缺口与工具、环境不可用；结构化返回成功不能单独算作分析正确。

### 2. 跑通一条自然语言 Web 任务

依赖：阶段 1。主要位置：[安全入口](../../packages/experimental/security-analysis/src/index.ts)、[controller](../../packages/experimental/security-analysis/src/workbench/controller.ts)、安全 preset 与 [UI 插件](../../packages/experimental/client-ui-security-analysis/src/client/index.ts)。

- [ ] S2.1 定义任务上下文字段和工作区关联；解析文件与环境，显式记录默认值，对缺失的引用明确报错。
- [x] S2.2 将经过身份验证的用户输入连接到项目选择、任务创建和资源关联。区分明确的用户指令、既有配置与模型推断；模型建议不能设置 operator 标记或制造批准。
- [ ] S2.3 在固定组合中补齐必要的通用文件、技能和执行工具。在执行时落实任务限制；仅展示工具或移除角色过滤不足以完成此项。
- [ ] S2.4 支持后续消息修订任务。范围收紧约束新调用，并取消或核对不兼容的在途工作；修订不能隐式扩大权限。
- [x] S2.5 同步交付最小工作区配置、对话入口和结果视图，跑通 Web 输入、采集、证据保存到报告的完整路径。

交付物：通过受支持 DSH 启动入口运行的真实端到端任务。验收：用户无需手动创建检查模板或选择 agent；普通任务仍能完成；shell、PTC 或 MCP 等其他调用路径不能绕过适用的执行策略。

### 3. 加强安全推理与工具使用

依赖：阶段 2 的任务与资源字段。主要位置：[provider 定义](../../packages/experimental/security-analysis/src/workbench/providers.ts)、[模型记录](../../packages/experimental/security-analysis/src/workbench/model.ts)、[角色指导](../../packages/experimental/security-analysis/src/workbench/roles.ts)，以及添加到安全组合的技能内容。

- [ ] S3.1 增加可组合的 Web、固件、嵌入式 Web 和 IoT 方法。依据目标与实际材料分类，保留不确定性，并在证据改变分析时更新标签。
- [x] S3.2 指导每项调查明确事实、假设、替代解释、可区分解释的检查和停止条件；现有记录能够表达时直接复用。
- [ ] S3.3 扩展 provider 指导，说明支持的输入、前置条件、资源、影响、有用结果字段、限制和失败恢复；区分安装、就绪与目标可访问。
- [ ] S3.4 根据缺少的证据选择工具。保留原始输出和不完整结果；区分假设被否定、方法不适用与资源不可用。
- [ ] S3.5 针对具体知识缺口使用现有证据检索和 DSH 网络搜索。记录来源及版本适用性；参考资料不能变成目标上的实际证据。
- [ ] S3.6 完成固件与嵌入式 Web、IoT 离线样例。仅在样例证明缺少操作时新增适配器，并覆盖执行、清理与证据行为。

交付物：可复用分析方法和明确的工具使用指导。验收：扫描命中、清点字符串与版本匹配在获得依据前仍是线索；相同失败调用能够停止；缺少能力时给出适用替代方案或准确限制。

### 4. 优化委派与独立验证

依赖：阶段 2 的任务修订；阶段 3 提供方法和工具指导。主要位置：安全入口、角色定义、[controller](../../packages/experimental/security-analysis/src/workbench/controller.ts)、[评估辅助函数](../../packages/experimental/security-analysis/src/workbench/assessment.ts) 与现有子 agent 服务。

- [ ] S4.1 分离专长标签与能力准入。将调查、验证和复核作为工作目的，保留现有角色权限；运行时验证仍通过获准的执行路径完成。
- [ ] S4.2 为解析后的委派补充已知证据、预期反馈、依赖及输入或结论修订；创建子 agent 前校验引用和允许访问的资产与资源。
- [ ] S4.3 在已有检查、jobs 和子 agent 上增加缺失证据准入、等价工作识别及就绪检查选择。低成本任务留给主 agent；依赖和资源所有权允许时才接纳并行工作。
- [ ] S4.4 对共享设备和可变环境复用资源键与互斥机制；隔离临时输出，处理取消、清理和重启，避免重复产生副作用。
- [ ] S4.5 合并计量主子 agent 工作量，预留准入额度和最终答复容量，结算实际用量，并执行可配置的无进展和失败上限。
- [ ] S4.6 分别整合新增观察、分析纠正与相反证据，使复核绑定精确结论和输入。缺失观察对应具体检查，或保留为明确局限。
- [ ] S4.7 完成带阳性和阴性对照的最小已授权 Web 验证闭环，明确纯静态路径和目标不可用路径，再将同一流程扩展到固件和 IoT 示例。
- [ ] S4.8 增加重复摘要委派、虚假新颖性、能力不可用、证据或复核过期、资源冲突、并发预算预留及取消回归。在宣称提升前，完成 S6.3 的同预算比较。

<a id="acceptance"></a>
## 验收场景

以下是计划中的检查项，列入此处不表示已经执行。

| 场景 | 必须观察到的结果 |
|---|---|
| 普通开发任务 | 文件、技能和允许的执行工具可用，不强制进入安全项目步骤 |
| 自然语言 Web 任务 | 选择工作区并发出一次请求后，可以获得带可核验证据的报告 |
| 含嵌入式 Web 的固件 | 方法能够组合，资产关系和结论限制明确 |
| 无设备的 IoT 材料 | 完成离线工作；不可访问的设备行为仍标为未验证 |
| 工具缺失或版本不兼容 | agent 选择适用且可用的方法，或明确报告阻塞，不假装成功 |
| 扫描或清点线索 | 没有充分实现或运行时证据时，线索不能成为已确认发现 |
| 简单任务与并行任务 | 简单任务避免委派；独立工作在不重复调查的前提下改善时间或质量 |
| 共享可变资源 | 冲突操作不能重叠；取消后明确资源所有权与清理结果 |
| 执行中收紧范围 | 父子 agent 均不能启动不允许的动作；不兼容的在途工作被取消或核对，并向用户显示无法避免的延迟 |
| 其他执行路径 | provider 直调、shell、PTC 与 MCP 调用执行相同的适用限制 |
| 不可信内容 | 网页、工具输出和子 agent 报告不能产生权限或扩大任务范围 |
| 证据冲突或发现变化 | 相反证据保持可见；旧复核不能确认已改变的结论 |
| 重启或重连 | 已保存证据与报告可访问，不盲目重放修改操作 |
| 历史项目与 Session | 读取、写入、恢复和导出保留旧数据；新默认值不会重新分类发现 |

<a id="validation"></a>
## 兼容性与验证

任务字段、角色绑定、能力规则和结果投影在所属实现更新前均属于设计。保留现有证据的不可变性。公开类型改变时同步更新消费者，对声明的持久化类型变更作确认，并在适用时遵循已发布格式迁移规则。Session 事件变化必须同时更新要求覆盖的 TypeScript、Python SDK 投影与预期输出。

对改动包执行定向行为测试，对产品可见组合执行非单元的真实 Loader/profile 测试，对模型可见行为补充无密钥录制会话快照。实现持有异步资源时增加生命周期与并发资源用例。外部工具能力声明由真实 provider 测试支持；UI 测试和真实模型 GIF 验证实际用户路径。

通过 [dsh-pre-push-checks](../../.agents/skills/dsh-pre-push-checks/SKILL.md) 选择提交前检查命令。文档遵循[文档规范](../AGENTS.md)，覆盖双语配对、链接和文档检查。根据改动文件选择构建、类型、打包和消费者检查；除非范围确实需要完整本地执行，否则全仓覆盖由 CI 负责。

量化验收阈值依据基线测量和样例已知结果确定。报告模型波动与失败尝试，不仅选取有利运行。运行能力声明需要环境证据，不能由模拟结果或报告外观替代。
