# 安全 Harness 路线图

[English](security-analysis.md) | 中文

## 摘要

本路线图记录截至 2026-09-21 的可选 DeepSeek Harness 安全扩展，是交付计划，不是支持声明。目标是可恢复的长链路安全检查：侦察 → 攻击面分析 → 漏洞评估与检索 → 受控安全验证。[包参考](../../packages/experimental/security-analysis/README.zh.md) 维护当前运行行为和工具兼容矩阵，[用户指南](../user/guide/security-analysis.zh.md) 维护启动方式。

## 功能 TODO

以下条目描述产品能力，不是测试清单。已有实现见“当前基础”；即使存在适配器或界面骨架，未勾选项仍表示功能尚未完整交付。

### P0：可用的逆向分析 Agent

- [ ] **项目首页与复盘**：在聊天输入框之外提供持久项目入口，展示资产、覆盖情况、阻塞及最新复盘；直接打开可读报告，关联证据和子 agent 摘要，不必手动搜索知识库。
- [ ] **ELF/PE 结构化分析**：用维护中的解析库提取头、节、段、符号、导入和相对地址，让模型依据解析字段推理，减少从十六进制文本计算偏移。
- [ ] **受管理的 Ghidra 工作流**：启动已配置 GUI、导入并绑定样本、显示分析进度，在项目内浏览反编译、汇编、交叉引用和允许的分析数据库修改。
- [ ] **有证据关联的独立复核**：持久化复核结论、支持/反对证据与未决判断，将纠正记录关联到原发现并呈现在复盘中。
- [ ] **长链路检查编排**：把依赖计划转为可执行任务，分配有边界的子任务，遇阻时继续独立检查，在明确核对状态后恢复工作。
- [ ] **项目预算**：强制限制累计委派次数、token/费用及重复失败次数，展示消耗，允许操作者暂停或调整限额。
- [ ] **可用的受控动态分析**：预览版本化观察/验证脚本，说明精确目标与影响，持续显示有界事件摘要，展示清理结果及静动态位置关联。

### P1：工具、知识与 Android 工作流

- [ ] **工具与环境管理页**：配置工具路径和版本，展示角色权限与就绪状态，管理本地 Docker/Kali 环境和资源占用，区分安装情况与可执行能力。
- [ ] **Android 分析工作流**：连接已授权设备或模拟器，导入 APK/DEX/SO，关联 Manifest 组件、Java/Kotlin 方法及 JNI 入口，并引导准备 Frida 前置条件。
- [ ] **知识工作流**：把项目发现和复盘整理为可审核的复用方法，增加结构化关系过滤、适用条件/版本，以及知识、发现和原始证据间的导航。
- [ ] **操作者交互**：提供清晰的计划批准/撤销、项目停止/恢复、实时任务进度与断线恢复；保留聊天，同时让领域操作容易找到。
- [ ] **可扩展角色与任务模板**：可注册角色工具策略、任务提示词、完成条件和环境要求，不必修改固定的内置角色表。

### P2：扩展安全子项目

- [ ] **Web 安全项目**：授权目标清点、暴露入口整理、会话/浏览器环境与受控验证模板，复用同一套证据和授权服务。
- [ ] **IoT 与固件项目**：固件组成和文件系统清点、架构识别、服务/配置分析，以及具备明确恢复方案的设备专项环境。
- [ ] **更多工具 provider**：只读 fastboot 清点及带资源限制的授权离线 john 审计；设备写入保持为独立授权能力。
- [ ] **远程实验室与语义检索**：增加远程环境所有权/清理和知识语义检索，同时保留项目隔离与精确证据检索。

<a id="baseline"></a>
## 当前基础

工作区已包含可选 Host/Web profile、证据日志与 FTS 索引、不可变制品、四阶段检查、验证计划授权、中断核对，以及 Ghidra/Frida/Android 专用适配器。内置二进制检查、角色工具权限和任务提示词支持协调者、侦察者、逆向分析员、研究员和复核者 Session。安全 Web 默认端口与通用 Web 分离。这些基础能力仍处于实验阶段。

借鉴 PentAGI 的专职委派、资料检索和精简结果报告，同时保留明确的项目/Session 角色、证据引用、用户授权及独立复核。提示词不将所有未来操作视为预先授权；子 agent 报告不能扩大范围或冒充用户。实现细节由[角色及提示词定义](../../packages/experimental/security-analysis/src/workbench/roles.ts) 维护。

已执行真实 Windows Frida 正常结束/取消，以及本机 Docker 生命周期验证。教程 hello_world AArch64 样本的真实 DeepSeek 调用已跑通导入、静态证据、检索和 fresh 子 agent 报告，但暴露了模型对 ELF 偏移和符号的错误解读。Ghidra GUI 集成、Android 设备分析、完整四阶段验收及真实模型 GIF 仍未完成。目前没有可用 Android 设备；模拟与无密钥回放不能替代这些检查。

<a id="delivery-milestones"></a>
## 交付里程碑

| 优先级 | 交付项 | 依赖 | 完成条件 |
|---|---|---|---|
| P0 | 受管理的 Ghidra GUI 启动、导入与程序绑定 | 兼容 Ghidra/JDK 和已编译管理扩展 | 导入授权 PE/ELF/SO，核对实测哈希，拒绝程序切换错误归属，验证并发读写租约、超时及 GUI 关闭 |
| P0 | Android 静动态闭环 | 已授权设备/模拟器、adb、JADX 和 Frida 前置条件 | 关联 Manifest 组件、Java/Kotlin 方法和 JNI 模块；覆盖设备断连、模块不符及不完整反编译；授权 APK 完成四阶段 |
| P0 | 持久化独立复核与委派验收 | 现有角色绑定和证据记录 | 持久化关联证据/版本的复核结论；通过真实 preset 执行 fresh 子 Session；拒绝外项目证据、角色越权及不兼容任务；保留复核 Session 链接 |
| P0 | 完整证据与恢复生命周期 | provider 生命周期钩子和制品存储 | helper 失败/输出洪泛时保存原始观察；核对持久化进程/容器所有权；重启不重放 spawn/注入；证明取消保留外部进程 |
| P1 | 工作台完整工具管理 | Host 清单及能力/健康结果 | 分别展示安装声明、实测版本、角色权限、就绪失败和租约占用；加入审核过的安装步骤和兼容检查，不开放模型任意 shell |
| P1 | 工作台操作完善 | 权威领域状态和生成的 Remote | 展示委派摘要、证据偏移、资料链接、复核状态与实时进度；测试停止/重连/核对；录制真实服务与模型 GIF |
| P1 | 知识质量与检索 | 项目证据和已审核共享经验 | 增加结构化关系过滤、多语言标识符/地址案例、隔离重建测试及来源版本复核；共享经验不能隐式成为项目证据 |
| P2 | Web 安全子项目扩展 | 可复用 provider/角色/任务注册及隔离环境 | 在授权测试应用交付允许范围内的目标导入、入口整理和经批准的有界验证，复用证据及授权生命周期 |
| P2 | IoT 子项目扩展 | 设备租约、镜像身份及复位/清理计划 | 先交付固件清点和只读镜像分析；环境与清理可复现后再加入设备专项验证 |

P0 完成首个逆向分析版本；P1 在闭环之后改善操作与维护；P2 引入新项目类型，不扩大首版授权范围。排期由依赖决定，所需环境落实前不承诺日期。

<a id="tool-and-environment-expansion"></a>
## 工具与环境扩展

| 领域 | 首版处理 | 下一步准入要求 |
|---|---|---|
| 二进制初筛 | 内置身份/十六进制/字符串观察 | 需要节区/导入元数据时优先采用维护中的解析库，保留不完整结果语义 |
| Ghidra、JADX、Frida、adb | 专用适配器与固定操作集 | 完成 P0 真实环境矩阵后再声明支持组合 |
| Kali/Docker | 用户选择本地镜像，管理任务自有生命周期并限制资源 | 固定已测试镜像摘要与工具版本，持久化所有权和诊断，不静默更换镜像 |
| fastboot | 仅安装/版本登记 | 将只读清点与设备写入 provider 分开；写入前具备设备身份、明确计划和恢复验收 |
| john | 仅安装/版本登记 | 增加已授权离线审计 provider，落实不可变输入、CPU/时限、输出处理和清理后再启用执行 |
| Web/IoT 专项工具 | 首版没有执行 provider | 同时注册资产类型、工具能力、角色策略、提示词、环境需求和证据适配器 |
| 远程实验室与虚拟机编排 | 延后 | 创建环境前明确凭据、传输信任、所有权核对、取消和清理 |
| 语义检索 | 延后 | 评估检索质量和项目隔离，同时保留可重建的精确全文检索 |

新增工具必须同时提供调用入口、有界执行、环境检查、证据采集、角色拒绝测试与清理。注册 provider 不代表工具已安装或就绪。安装、系统提权和设备修改保留为明确的操作者行为。公开资料研究提示词排除私有样本数据；可强制执行的网络出口/数据防泄漏控制仍属后续工作。

<a id="release-acceptance"></a>
## 发布验收

1. 授权 Android APK/DEX/JNI、Windows PE、Linux ELF 样本完成四阶段，包含已验证、已反驳和证据不足的发现，并记录精确工具/运行时版本及原始证据。
2. 通过真实执行入口拒绝程序切换、PID 复用、过期批准、脚本变更、越权资产、子 agent 越权和原始 shell/PTC/MCP 绕过。
3. 覆盖断连、目标退出、脚本异常、取消、输出洪泛、清理失败和 Host 重启，验证无副作用重放，清理失败后的不确定性明确可见。
4. 运行真实 Loader/profile 测试、无密钥 Session 快照、持久化类型检查、构建/类型/文档检查和浏览器流程，分别报告外部工具模拟与真实环境结果。
5. 只发布实际验证过的环境组合，列明剩余限制；GUI PR 附带真实服务、真实模型流程录制的 Web GIF。
